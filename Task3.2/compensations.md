# Компенсирующие транзакции

| Шаг сценария | Компенсирующее действие | Риск, который устраняется |
|---|---|---|
| Резервирование приёма в системе расписания | Отменить резерв по appointmentId, если последующие шаги не завершились. Повторная отмена безопасна. | Слот остаётся занятым, хотя пациент не получил услугу и операция не завершена. |
| Проведение оплаты | Вернуть подтверждённую сумму по paymentId, если резервирование анализов или подтверждение приёма окончательно не удалось. Для возврата используется отдельный постоянный ключ операции. | Деньги списаны за незавершённую запись; повтор компенсации может привести к повторному возврату. |
| Резервирование сдачи анализов в LIS | Отменить резерв по labReservationId, если подтвердить приём не удалось. Повторная отмена безопасна. | Лабораторное время остаётся занятым для отменённой операции. |

## Порядок компенсаций

Компенсируются только успешно выполненные шаги, в обратном порядке: резерв анализов → оплата → резерв приёма.

Проверка полиса не требует компенсации, поскольку не изменяет данные.

При тайм-ауте платежа сначала выясняется его статус. Возврат запускается только для подтверждённого списания.

Компенсации также могут завершаться ошибкой. Backend сохраняет их состояние, повторяет безопасные вызовы и передаёт неустранимые сбои на ручной разбор с оповещением. Пока возврат не подтверждён шлюзом, пациент видит «Возврат обрабатывается».
