# Выбор типа SAGA

Используем оркестрируемую SAGA: backend управляет последовательностью шагов и хранит состояние операции. Сценарий включает расписание, 1С, платёжный шлюз и LIS, поэтому централизованная координация позволяет явно определить порядок действий и компенсаций. При сбое backend восстанавливает выполнение по сохранённому состоянию, а повторные команды обрабатываются идемпотентно. Хореография усложнила бы отслеживание общего результата и управление возвратом денег.

## Правила выполнения

- Проверка ДМС выполняется только при использовании полиса. При недоступности проверки операция не продолжается как будто полис подтверждён.
- Показан сценарий с платной частью услуги. При нулевой сумме шаг оплаты пропускается.
- Backend возвращает operationId, а приложение получает состояние отдельными запросами. Длительная операция не удерживает один HTTP-запрос.
- Возврат пользователя с платёжной страницы не подтверждает оплату: backend проверяет статус у шлюза.
- Тайм-аут означает неизвестный результат шага. Сначала выполняется проверка статуса или безопасный повтор с тем же ключом.
- Временный резерв приёма имеет срок действия. Если после оплаты подтвердить его уже нельзя, запускаются компенсации.
- Сбой уведомления не отменяет успешную запись: доставка повторяется отдельно.
- Методы резервирования и отмены в LIS, а также поддержка ключей операций зависимыми системами требуют проверки и при необходимости доработки.
